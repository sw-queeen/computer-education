문맥교환
Context Switch
CPU가 실행 중인 프로세스를 교체할 때, 현재 프로세스의 상태(문맥)를 저장하고 새 프로세스의 상태를 복원하는 커널의 작업 전체. 이 구간은 순수 오버헤드로 간주된다.
발생 조건 · 트리거
타이머 인터럽트
선점형 스케줄러가 타임 슬라이스 만료를 감지하면 강제로 CPU를 회수한다
I/O 요청·이벤트 대기
실행 중인 프로세스가 I/O를 요청하면 Waiting 상태로 전환되고 다른 프로세스가 CPU를 점유한다
시스템 콜
프로세스가 커널에 서비스를 요청할 때 일부 시스템 콜은 문맥교환을 유발한다
고우선순위 프로세스 도착
Ready 큐에 더 높은 우선순위 프로세스가 들어오면 현재 프로세스를 선점한다
문맥교환 절차 · 6단계
01
인터럽트 / 시스템 콜 발생
문맥교환의 트리거. P1 실행이 일시 중단된다.
02
P1 문맥 저장 → PCB₁핵심
PC·레지스터·SP·플래그 등 CPU 상태 전체를 P1의 PCB에 기록한다.
03
P1 상태 전환 → Ready / Waiting
원인에 따라 Ready 큐 또는 Waiting 큐로 이동한다.
04
스케줄러가 P2 선택
CPU 스케줄러가 Ready 큐에서 다음 실행할 프로세스 P2를 결정한다.
05
P2 문맥 복원 ← PCB₂핵심
P2의 PCB에 저장된 상태를 레지스터에 적재한다.
06
P2 실행 재개
디스패처가 커널 모드 → 사용자 모드로 전환하고 P2를 실행한다.

RunningCPU 점유 중 (실행 중)문맥교환의 출발점 또는 도착점

체크 포인트
혼동 주의문맥교환 ≠ CPU 스케줄링. 스케줄링은 "누구를 실행할지 결정"하는 정책, 문맥교환은 그 결정을 "실제로 구현"하는 메커니즘.
혼동 주의문맥교환 ≠ 인터럽트 처리. 커널 스택 저장은 인터럽트 처리, 다른 프로세스로의 전환은 문맥교환.
핵심 암기PCB 저장 핵심 3요소: PC + 범용 레지스터 + SP. 이 세 가지가 없으면 프로세스 재개 불가.
