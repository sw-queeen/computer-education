문맥교환
문맥교환(Context Switch)은 CPU가 실행 중인 프로세스를 교체할 때, 현재 프로세스의 상태를 저장하고 새 프로세스의 상태를 복원하는 커널의 작업 전체를 말한다. 이 구간 동안 CPU는 유용한 작업을 하지 못하므로 순수 오버헤드로 간주된다.
01 발생 조건
01
타이머 인터럽트
선점형 스케줄러가 타임 슬라이스 만료를 감지하면 강제로 CPU를 회수한다.
02
I/O 요청 또는 이벤트 대기
실행 중인 프로세스가 I/O 작업을 요청하면 Waiting 상태로 전환되고, 다른 프로세스가 CPU를 점유한다.
03
시스템 콜
프로세스가 커널에 서비스를 요청할 때 일부 시스템 콜은 문맥교환을 유발한다.
04
고우선순위 프로세스 도착
선점형 스케줄러에서 Ready 큐에 더 높은 우선순위 프로세스가 들어오면 현재 프로세스를 선점한다.
02 문맥교환 절차 — 6단계
인터럽트 / 시스템 콜 발생
문맥교환의 트리거. P1 실행이 일시 중단된다.
P1 문맥 저장 → PCB₁
PC·레지스터·SP·플래그 등 CPU 상태 전체를 P1의 PCB에 기록한다.
P1 상태 전환 → Ready / Waiting
원인에 따라 Ready 큐 또는 Waiting 큐로 이동한다.
스케줄러가 P2 선택
CPU 스케줄러가 Ready 큐에서 다음 실행할 프로세스 P2를 결정한다.
P2 문맥 복원 ← PCB₂
P2의 PCB에 저장된 상태를 레지스터에 적재한다.
P2 실행 재개
디스패처가 커널 모드 → 사용자 모드로 전환하고 P2를 실행한다.
03 프로세스 상태 전이 — 5가지
New생성 중문맥 없음 (PCB 초기화 중)
RunningCPU 점유 중문맥교환의 출발점 또는 도착점
ReadyCPU 할당 대기 중문맥교환 후 이 상태로 전환되거나, 이 상태에서 선택됨
WaitingI/O 또는 이벤트 대기 중Running → Waiting 전환 시 문맥 저장 발생
Terminated실행 완료·종료PCB 해제. 더 이상 복원 불필요

05 오버헤드 & 성능 고려사항
디스패처 지연(Dispatcher Latency)
문맥교환에 소요되는 순수 시간. 이 시간 동안 CPU는 사용자 프로세스를 실행하지 못한다. 운영체제 설계의 핵심 최적화 대상.
캐시 오염(Cache Pollution)
프로세스 전환 시 이전 프로세스가 캐시에 올려둔 데이터가 무효화된다. 새 프로세스는 콜드 캐시에서 시작하므로 초기 실행 속도가 느려진다.
TLB 플러시(TLB Flush)
TLB는 페이지 테이블 캐시. 주소 공간이 바뀌면 TLB를 플러시해야 한다. ASID 태깅으로 플러시를 줄일 수 있다.
성능 개선 — 스레드 전환
스레드 전환은 주소 공간이 공유되므로 TLB 플러시 없이 레지스터만 교환 → 문맥교환보다 빠름.

07 논술 답안 구조
개념 정의
문맥교환 정의: CPU 실행 프로세스 교체 시 현재 상태 저장 + 새 프로세스 상태 복원
문맥(Context): PCB에 저장되는 CPU 상태 정보 전체
발생 조건 및 절차
트리거: 타이머 인터럽트 / I/O 요청 / 시스템 콜 / 고우선순위 프로세스 도착
절차: P1 저장(PCB₁) → P1 큐 이동 → P2 선택 → P2 복원(PCB₂) → P2 실행
PCB 구성 & 역할
PCB 저장 핵심: PC·레지스터·SP·플래그·메모리 맵·파일 디스크립터 등
PCB 없으면 중단된 프로세스 재개 불가
오버헤드 & 의의
문맥교환 중 CPU는 유용한 작업 수행 불가 → 순수 오버헤드
멀티태스킹 구현의 핵심 메커니즘. 스레드 전환은 프로세스 전환보다 경량
08 체크 포인트
혼동 주의문맥교환 ≠ CPU 스케줄링. 스케줄링은 "누구를 실행할지 결정"하는 정책, 문맥교환은 그 결정을 "실제로 구현"하는 메커니즘이다.
혼동 주의문맥교환 ≠ 인터럽트 처리. 인터럽트 발생 시 커널 스택 저장은 인터럽트 처리이고, 다른 프로세스로의 전환이 문맥교환이다.
핵심 암기PCB 저장 핵심 3요소: 프로그램 카운터(PC) + 범용 레지스터 + 스택 포인터(SP). 이 세 가지가 없으면 프로세스 재개 불가.
핵심 암기스레드 문맥교환 < 프로세스 문맥교환: 주소 공간을 공유하므로 TLB 플러시 없이 레지스터만 교환 → 경량.
